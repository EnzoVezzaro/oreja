# Distribution

## Current artifacts

```bash
./scripts/build.sh
open build/Oreja.app
```

`build/Oreja.app` (~2.8 MB) is assembled by `scripts/build.sh`:

- `Contents/MacOS/Oreja` — the SwiftUI menu bar app.
- `Contents/Frameworks/libOrejaCore.dylib`, `libOrejaAudio.dylib`, `libOrejaMedia.dylib` — signed
  before the app, with `@rpath` resolution to `../Frameworks`.
- `Contents/Resources/AppIcon.icns` — generated by `tools/IconBuilder`.
- `Contents/Info.plist` — `LSUIElement`, minimum macOS 14.2, usage descriptions, bundle identifier
  `app.oreja.van-gogh`.
- Entitlements: `com.apple.security.device.audio-input`,
  `com.apple.security.automation.apple-events`; sandbox disabled.

Signing is **ad-hoc** (`codesign -s -`) and deliberately **without** the hardened runtime: an
ad-hoc signature carries no team identity, so hardened runtime library validation rejects Oreja's
own nested dylibs and the app aborts in dyld at launch. The hardened runtime is enabled
automatically when a real identity is supplied through `OREJA_SIGN_IDENTITY`. `codesign
--verify --strict` passes locally. The build is **not notarized**: no Developer ID credentials were
available, and this document does not claim otherwise.

`build/Oreja.dmg` is a local UDZO disk image containing that ad-hoc-signed app. It is suitable for
local testing and packaging review, but it is not yet a public release artifact: it still needs
Developer ID signing, notarization, release notes and a clean-Mac install test.

The dylibs are linked with `@rpath` install names and copied into `Contents/Frameworks`, so the
bundle is self-contained. Verified by hiding `build/lib` and relaunching: the app still starts and
maps only its own `Contents/Frameworks` copies.

## Install

1. Build (or copy) `Oreja.app` to `/Applications`.
2. Open it. On the first launch, onboarding requests system audio recording and Music automation.
3. Enable launch at login in onboarding or Settings if desired.

Because the app is ad-hoc signed, macOS may refuse the first launch on another Mac
("cannot be opened because the developer cannot be verified"). For local testing only:
System Settings › Privacy & Security → "Open Anyway", or right-click the app → Open. Never instruct
users to disable Gatekeeper globally.

Rebuilding changes the code signature. TCC may then treat the app as new and require permissions
again. This is normal for unsigned development builds.

## Developer ID signing and notarization (not performed)

Prerequisites: an Apple Developer Program membership, a "Developer ID Application" certificate in
the login keychain, and an app-specific password or API key for notarytool.

```bash
# 1. Build and sign in one step with a real identity (hardened runtime + timestamp).
OREJA_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" ./scripts/build.sh

# 2. Notarize.
ditto -c -k --keepParent build/Oreja.app build/Oreja.zip
xcrun notarytool submit build/Oreja.zip \
  --apple-id "you@example.com" --team-id "TEAMID" --password "@keychain:AC_PASSWORD" \
  --wait
xcrun stapler staple build/Oreja.app
spctl --assess --type execute --verbose build/Oreja.app   # should say accepted

# 3. Optional disk image.
hdiutil create -volname "Oreja de Van Gogh" -srcfolder build/Oreja.app \
  -ov -format UDZO build/Oreja.dmg
```

`./scripts/build.sh --no-sign` plus manual `codesign` calls also works if you prefer to control
signing yourself; sign `Contents/Frameworks/*.dylib` before the app.

Store notarytool credentials once with
`xcrun notarytool store-credentials AC_PASSWORD --apple-id … --team-id … --password …`.
Do not commit credentials or API keys.

## Sandbox / App Store

The sandbox is intentionally off. A sandboxed build would need the same two entitlements plus an
Apple Events temporary exception; App Store review may reject the automation model. If App Store
distribution is attempted, re-verify process taps under the sandbox first. Do not weaken privacy or
security controls to pass review.

## Versioning

`CFBundleShortVersionString` and `CFBundleVersion` live in `packaging/Info.plist` (currently
`0.1.0` / `1`). Bump both for every distributed build. There is no auto-updater.

## Release checklist

- [ ] `./scripts/test.sh` passes.
- [ ] `./scripts/build.sh` succeeds, `open build/Oreja.app` starts it, and `pgrep -x Oreja` stays
      alive (a dyld/library-validation failure exits in about a second and writes a crash report).
- [ ] `codesign --verify --strict` passes; entitlements are the expected three.
- [ ] Manual acceptance test with ChatGPT Voice and Apple Music (`test-evidence.md`).
- [ ] Permissions work on a clean user account.
- [ ] Gatekeeper/notarization passes on a clean Mac.
- [ ] Trademark and name search completed.
- [ ] Release notes list verified and unverified behavior honestly.
